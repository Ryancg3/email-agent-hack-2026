# Deploy to Render (always on)

This runs the web app and the 5-minute scheduler as one Render web service, so the
agent keeps working when your laptop is off. The SQLite database lives on a 1 GB
persistent disk that survives deploys and restarts.

**Cost:** about $7.25 a month: the Starter instance ($7) plus a 1 GB disk ($0.25).
The free instance type can't be used, because it has no disk and goes to sleep. It
goes on the same Render bill as your other services. Anthropic API usage is billed
separately, the same as when you run it locally.

## What gets deployed

| File | What it does |
| --- | --- |
| `render.yaml` | Blueprint: one Docker web service on the Starter plan, a 1 GB disk at `/data`, health check on `/health`, and the environment variables |
| `Dockerfile` | Python 3.13 image with the dependencies and collected static files |
| `deploy/start.sh` | Runs migrations, then gunicorn and `run_scheduler` side by side. If either stops, the container exits and Render restarts it |

Environment variables:

| Variable | Where it comes from | Purpose |
| --- | --- | --- |
| `ANTHROPIC_API_KEY`, `TOKEN_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | You enter them when creating the Blueprint | Same as in `.env` |
| `DJANGO_SECRET_KEY` | Generated by Render | Signs sessions |
| `DJANGO_DEBUG`, `DATABASE_PATH` | `render.yaml` | Debug off, database on the disk |
| `APP_HOST` | Automatic | Defaults to your `onrender.com` hostname. Set it only for a custom domain |
| `SIGNUP_CLOSED` | You add it after step 4 | `1` blocks new sign-ups |

## 1. Get the code onto GitHub's default branch

Render reads `render.yaml` from the branch you connect. Merge the deploy PR into
`main` first, or pick the PR's branch in step 2.

## 2. Create the service from the Blueprint

1. In the [Render dashboard](https://dashboard.render.com), click **New > Blueprint**.
2. Connect the `email-agent-hack-2026` repository. If Render can't see it, click
   **Configure account** and give Render's GitHub app access to the repo.
3. Render shows one service, `email-agent`, with a disk. It asks for the four values
   marked `sync: false`. Paste them from your `.env`:
   - `ANTHROPIC_API_KEY`
   - `TOKEN_KEY`. Use the same one as in `.env`, or generate a new one with
     `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
     If you ever change it later, you'll need to reconnect Google.
   - `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`
4. Click **Apply**. The first build takes a few minutes.

When it's live, the service page shows its URL, such as
`https://email-agent.onrender.com`. If the name was taken, Render adds a suffix, such
as `email-agent-x1y2`. Use your real URL in the steps below.

Check that `https://<your-service>.onrender.com/health` returns `{"status": "ok"}`.

## 3. Update your Google OAuth client

In [Google Cloud Console](https://console.cloud.google.com/apis/credentials), open your
**Web application** OAuth client and add this to **Authorized redirect URIs**, next to
the localhost ones:

```
https://<your-service>.onrender.com/google/callback/
```

The trailing slash matters. Save it. It can take a few minutes to apply.

Then go to **Google Auth Platform > Audience** (the OAuth consent screen) and check
the **Publishing status**:

- **Testing:** Google expires refresh tokens after 7 days, so the agent would stop
  every week until you reconnect. Click **Publish app** to move it to **In production**.
- **In production** without verification is fine for your own use. Google shows a
  "Google hasn't verified this app" screen when you connect. Click **Advanced**, then
  **Go to ... (unsafe)**, once.

## 4. Set up your account

1. Open `https://<your-service>.onrender.com`, sign up and connect Google.
2. Edit your labels on the **Labels** tab and turn the agent on.
3. Close sign-ups so nobody else can run the agent on your Anthropic key. On the
   service's **Environment** page, add `SIGNUP_CLOSED` with the value `1` and save.
   Render redeploys. Your account stays.

The hosted app starts with an empty database, separate from your local `app.db`, so
you sign up and connect Google once more there. It only handles mail that arrives
after you connect.

Then **stop `make dev` on your laptop**, or turn the agent off in your local
dashboard. Otherwise both copies label each email and draft duplicate replies.

## Everyday use

| To | Do |
| --- | --- |
| Ship new code | Push to the connected branch. Render redeploys automatically |
| See what the agent is doing | The service's **Logs** tab. Look for `running for <email>` every 5 minutes |
| Open a shell on the machine | The service's **Shell** tab |
| Create an admin login for `/admin/` | In **Shell**: `python manage.py createsuperuser` |
| Restart | **Manual Deploy > Restart service** |
| Pause it | **Settings > Suspend service**. The disk is kept |

Notes:

- A service with a disk runs as exactly one instance, which is what the scheduler
  needs. Don't try to scale it up.
- Each deploy has a few seconds of downtime while the old instance stops before the
  new one starts. The scheduler picks up any missed emails on its next run.
- Render takes a daily snapshot of the disk. You can restore one from the service's
  **Disks** page.

## Troubleshooting

- **`Bad Request (400)`:** the host isn't allowed. With a custom domain, add
  `APP_HOST` with that domain on the **Environment** page.
- **Google says `redirect_uri_mismatch`:** the URI in step 3 must match exactly,
  including `https://` and the trailing slash.
- **The agent stops after a week:** your OAuth app is still in Testing. See step 3,
  then reconnect Google from the dashboard.
- **Deploy fails with `KeyError: 'TOKEN_KEY'`:** a value from step 2 is missing. Add it
  on the **Environment** page.
